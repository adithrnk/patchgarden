Contributing to PatchGarden 🌱

Thanks for your interest in contributing to PatchGarden! Every thoughtful contribution helps make open source more welcoming to beginners.

Ways to contribute

You do not need to be an experienced programmer to help. You can contribute by:

* Reporting bugs or suggesting features.
* Improving the design and mobile experience.
* Fixing spelling, grammar, or documentation.
* Improving accessibility.
* Adding translations.
* Testing the website on different devices and browsers.
* Improving JavaScript functionality.
* Helping new contributors understand the project.

Before you start

1. Read the README.md file.
2. Search existing issues to avoid duplicating work.
3. Open an issue to discuss larger changes before implementing them.
4. Make sure you have permission to use any images, icons, fonts, or other assets you contribute.

Development setup

PatchGarden is a lightweight frontend project built with HTML, CSS, and JavaScript.

1. Fork the repository on GitHub.
2. Clone your fork:

git clone https://github.com/YOUR-USERNAME/PatchGarden.git

3. Open the project directory.
4. Open index.html in a browser, or use a local development server.
5. Make your changes and test them before submitting a pull request.

Replace YOUR-USERNAME with your GitHub username.

Code guidelines

* Keep code readable and straightforward.
* Use descriptive variable and function names.
* Preserve responsive behavior on mobile and desktop.
* Consider keyboard navigation and accessibility.
* Avoid unnecessary dependencies.
* Do not commit API tokens, passwords, or other secrets.
* Handle network errors gracefully.
* Test new features in a browser before submitting.

Commit messages

Use short, descriptive commit messages, for example:

* Fix mobile navigation spacing
* Improve repository validation
* Add Malayalam translation
* Update contribution documentation

Submitting a pull request

1. Create a branch for your change.
2. Make and test your changes.
3. Commit your work with a clear message.
4. Push the branch to your fork.
5. Open a pull request against the original repository.
6. Describe the problem, your solution, and any testing you performed.
7. Include screenshots for significant visual changes when useful.

Community standards

Be respectful, patient, and constructive. Welcome contributors of all experience levels. Harassment, discriminatory language, and personal attacks are not acceptable.
